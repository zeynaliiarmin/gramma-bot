## ۳) باگ ۱ — دکمه‌های Inline Keyboard

**ریشه‌یابی:**
1. `run.py` بدون `allowed_updates` بود → تلگرام ممکن بود آپدیت‌های callback را ندهد. ✅ اصلاح شد (لیست صریح: message، edited_message، callback_query، inline_query، web_app_data).
2. یک **race condition** واقعی در `get_or_create_user` (خطای `UNIQUE constraint failed: users.id`) هنگام پردازش آپدیت‌های هم‌زمانِ یک کاربر، هندلر را کرش می‌داد → دکمه بی‌صدا کار نمی‌کرد. ✅ با upsert اتمیک (`INSERT … ON CONFLICT DO NOTHING`) رفع شد.
3. هندلر catch-all اضافه شد: هر callback بدون هندلر، **لاگ می‌شود** و به کاربر جواب مناسب می‌دهد (دیگر هیچ دکمه‌ای بی‌صدا بی‌اثر نمی‌ماند).

**تست:** همه ۱۰ callback منوی کامل بررسی شدند که هندلر واقعی دارند؛ بوت زنده علیه ربات ادمین بدون خطا.

## ۴) باگ ۲ — مینی‌اپ «دسترسی ممکن نیست»

- اسکریپت اجباری `telegram-web-app.js` به `index.html` اضافه شد (و در بیلد prod حفظ می‌شود).
- اعتبارسنجی **HMAC-SHA256 initData** با توکن ربات پیاده شد (ماژول `app/core/security/tg_initdata.py` + endpoint جدید `POST /api/auth/verify`):
  - `hash` همیشه با کلید مشتق‌شده از توکن ربات چک می‌شود؛ `initDataUnsafe.user.id` **هرگز** به‌تنهایی قبول نمی‌شود.
  - باز شدن مستقیم در مرورگر یا از ربات دیگر → پیام «دسترسی ممکن نیست» و **هیچ داده‌ای نمایش داده نمی‌شود**.
- بلیط HMAC امضاشده با `ENCRYPTION_KEY` (باعتبار ۲۴ ساعت) در **sessionStorage** (نه localStorage نه کوکی) نگه داشته و در هر درخواست به‌صورت هدر `X-Mini-App-Hash` ارسال می‌شود.
- دکمه WebApp ربات حالا URL را از `MINIAPP_PUBLIC_URL` می‌سازد (در `.env` = آدرس Vercel).
- **CORS** فقط برای `MINIAPP_PUBLIC_URL` / `PUBLIC_BASE_URL` باز است.
- **تست زنده:** initData جعلی → `403`؛ initData معتبر امضاشده با توکن ادمین → `200` + بلیط؛ `/api/me` بدون هدر → `401`.
